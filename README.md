# AI 伴读 · 通用阅读器

一款「沉浸式 AI 伴读」阅读器：**导入任意小说文本 → 翻页阅读 → 在当前页唤起书中人物，以第一人称对话，且每次回答严格只基于当前阅读进度（绝不剧透）**。

这是《微信读书 AI穿书·人物视角沉浸式伴读系统》产品方案中「模块二 · AI 沉浸式伴读」核心功能的可运行实现，服务于秋招作品集。

## 核心设计

| 产品方案的承诺 | 本实现如何落地 |
|---|---|
| 防剧透硬隔离（P0 底线） | 后端只把「已读进度及之前」的章节喂给模型，之后的章节物理上不进入上下文 |
| 原著一致性 / 不 OOC | System 提示词固化「第一人称 + 人设锚定 + 禁止脱离原著」铁则 |
| 每次问答只基于当前进度 | 无多轮历史，每次回答都从当前进度重新检索（避免历史对话泄露剧透） |
| 无感化嵌入 | 阅读页内直接唤起人物，不跳出阅读流程 |
| 防过度娱乐化 | 拒绝闲聊、幻觉时统一兜底话术 |

## 召回策略（长篇小说怎么把「已读内容」喂给 LLM）

DeepSeek 上下文约 64K token（≈ 4 万字），而长篇小说动辄 30–50 万字，**全量直喂不可能**。本实现用三层组合，在「防剧透硬隔离」之内构建每次问答的上下文：

| 层 | 内容 | 作用 |
|---|---|---|
| 背景摘要 | 早期章节压缩成 300 字摘要（缓存复用） | 让模型知道「全书讲什么、谁是谁」 |
| 关键词检索 | 对早期章节做中文 2-gram 匹配，召回与提问相关的片段 | 读者问到早期伏笔时，能捞回具体原文 |
| 近期原文 | 最近 3 章保留原文 | 保证「当前场景」细节准确 |

- **硬隔离边界**：三层都只从 `chapters[:进度+1]` 里取，之后的章节物理上不存在，剧透无从发生。
- **降级**：无 API key 时摘要生成失败，自动退化为「近期原文 + 关键词检索」，链路仍完整可演示。
- **生产版**：关键词检索 → embedding 语义检索（处理同义词）；摘要 → 增量摘要 + 向量库（GraphRAG）。

## 功能

- 导入 `.txt`（自动识别 UTF-8 / GBK / UTF-16 编码）与 `.epub`（按 spine 抽取章节）
- 自动分章（`第X章/回/卷/节` / `Chapter N`，无标记则按段落切块）
- 翻页阅读（按钮 + 键盘 `←`/`→`），实时记录当前页所在章节作为防剧透进度
- 章节目录 + 跳章（长篇小说一键跳转），阅读进度本地保存（刷新/重开回到上次位置）
- 字号调节（14–24px）+ 夜间模式，阅读设置本地记忆
- **长文本召回**：早期章节压成背景摘要 + 关键词检索召回相关片段 + 近期原文，见下「召回策略」
- 人物自动抽取（DeepSeek 从开篇提取 name/介绍/首次出场章）+ 手动添加
- 未出场人物自动锁定，防止从交互层剧透
- 进度锚定视角对话（第一人称，200 字内，防剧透/防闲聊/防幻觉铁则）
- 划选段落 → 第一人称视角解读
- 真实 DeepSeek API + **降级兜底**（无 key / 断网时仍可完整演示交互链路）

## 技术架构

```
前端(静态) ──HTTP──> FastAPI 后端
                        ├─ 数据层  anti_spoiler.py  已读章节硬隔离 + 上下文构建（摘要+检索+近期原文）
├─ 召回层  retrieval.py / summarizer.py   关键词检索 + 早期章节背景摘要
                        ├─ 模型层  prompt.py        System 铁则（对应方案 5.8）
                        ├─ 校验层  （Prompt 内置防剧透/防闲聊/防幻觉铁则）
                        └─ 应用层  llm.py / character_extract.py   DeepSeek + mock 兜底
```

## 快速开始

```bash
# 1. 进入后端目录，安装依赖（Python 3.10+）
cd backend
pip install -r requirements.txt

# 2. 配置 DeepSeek key（复制 .env.example 为 .env 并填入）
cp .env.example .env    # Windows 下手动复制改名

# 3. 启动
uvicorn main:app --reload

# 4. 浏览器打开
#    http://127.0.0.1:8000
```

> 不填 key 也能跑：对话会走「降级演示」回复，可完整体验交互，只是非真实 AI 生成。

## 演示路径

1. 启动后点「导入小说」，选 `sample/雾港_示例.txt`（原创示例，3 章 3 人物）——先看分章、翻页、人物抽取、对话全链路跑通。
2. 面试演示可导入你自己的《三体》等 txt：人物抽取、按进度对话、切到不同章节看「未出场人物被锁定」与「回答口径随进度变化」，直观展示防剧透。

## 上线前差距（MVP → Production，面试可主动讲）

- **存储**：JSON 文件 → 数据库（SQLite/PostgreSQL）+ 对象存储
- **检索**：章节硬过滤 → 向量库 + GraphRAG（方案 5.8 的完整检索层）
- **多用户**：无账号体系 → 用户隔离、鉴权、限流
- **成本控制**：方案 5.5 的四层管控（大小模型路由 / 滑动窗口摘要 / 语义缓存 / 会员分级）尚未实现
- **合规**：商用需走公版书 + 内容安全网关（方案 5.8 校验层的前置合规拦截）

## 面试叙事要点

- **北极星指标**：功能覆盖书籍的完读率提升幅度（≥30%），而非对话轮数/时长。
- **核心判断**：主动拒绝「剧本生成 / 代入偏离原著 / 角色相遇」等更「好玩」的功能，因为产品定位是「帮用户读完一本书」，不是「聊天娱乐」。
- **防剧透是第一优先级**：从数据层（硬隔离）到交互层（未出场人物锁定）到模型层（进度截止铁则）三层兜底。
